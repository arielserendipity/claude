# 평균 탐구 활동 — 균형점 모델 × 막대 모델

초등학생이 **시소 그림(추·받침점)**과 **막대 그림**을 오가며 평균을 스스로 발견하도록 돕는 AI 통합 웹 앱입니다.
학생 화면에는 제목이 **“활동 1”, “활동 2”**로만 보입니다. 활동 2는 ‘정해진 설명을 쓰고 통과하기’가 아니라 **‘다른 그림을 예상하고, 자료를 바꾸어 시험하고, 내 자료로 확인하기’**로 진행되며, 학생에게는 판정을 보여 주지 않습니다.

| 학생에게 보이는 이름 | 교사용 제목 |
| --- | --- |
| 활동 1 | 균형점 모델 예제 풀기 |
| 활동 2 | 균형점 모델과 막대 모델 연결하기 |

## 실행하기

**필요한 것:** Node.js 20 이상

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 등 입력 (없어도 실행됨)
npm run dev                  # http://localhost:3000
```

배포(한 서버에서 화면 + API):

```bash
npm run build
NODE_ENV=production npm start
```

활동 2의 서술형 채점은 `server.ts`가 서버에서 **Claude API**를 불러 처리합니다. API 키는 서버에만 있고 학생 브라우저로 나가지 않습니다. 활동 1은 학생이 기다리지 않도록 AI 없이 규칙으로 바로 진단합니다.

### 학생 태블릿으로 쓰기 (Render 무료 배포)

학생마다 자기 태블릿으로 들어오려면 인터넷 주소가 있는 서버에 올려야 합니다. 이 저장소에는 [Render](https://render.com) 설정 파일(`render.yaml`)이 들어 있어서 아래 순서만 따르면 됩니다.

1. **코드 합치기**: GitHub의 PR 페이지에서 초록색 **Merge pull request** → **Confirm merge**를 누릅니다. (Render는 `main` 브랜치를 올립니다.)
2. **Render 가입**: render.com에서 **GitHub 계정으로 가입**합니다.
3. **배포 만들기**: 대시보드 **New** → **Blueprint** → 이 저장소를 고릅니다. 입력 칸이 나오면:
   - `ANTHROPIC_API_KEY`: Claude API 키 (채팅이나 GitHub에는 절대 붙여 넣지 마세요)
   - `VITE_TEACHER_PIN`: 교사용 대시보드 잠금 번호 (예: 네 자리 숫자) — 학생 태블릿에서 ⚙️를 눌러도 못 열게
   - `VITE_GOOGLE_SHEETS_URL`: 비워 두어도 됩니다 (아래 5번)
   - **Apply**를 누르고 3~5분 기다리면 `https://average-activity-xxxx.onrender.com` 같은 주소가 생깁니다.
4. **학생에게 주소 알려 주기**: 칠판에 적거나 QR 코드로 나눠 줍니다. 무료 요금제는 15분 동안 아무도 안 쓰면 잠들어서 첫 접속에 1분쯤 걸리니, **수업 몇 분 전에 선생님이 먼저 한 번 열어** 두세요.
5. **모든 학생 결과를 한곳에서 보기** (선택): 학생 기록은 각 태블릿에 따로 저장되므로, 한꺼번에 보려면 구글 시트를 연결합니다. 앱의 ⚙️ 교사용 대시보드에 있는 Apps Script 코드를 구글 시트([확장 프로그램] → [Apps Script])에 붙여넣고 웹 앱으로 배포한 뒤, 받은 URL을 Render의 **Environment** 화면에서 `VITE_GOOGLE_SHEETS_URL`에 넣고 **Manual Deploy**를 누릅니다. 그러면 모든 태블릿의 답안·AI 분석이 시트에 한 줄씩 쌓입니다.

요금 관리:
- Claude는 **활동 2 서술형 답을 제출할 때만** 부릅니다(활동 1은 호출 없음). 호출은 기본으로 **분당 120회, 하루 1000회**까지만 하고, 넘으면 자동으로 규칙 채점으로 대신합니다(`GRADER_MAX_CALLS_PER_MINUTE`, `GRADER_MAX_CALLS_PER_DAY`로 조정).
- Anthropic Console의 사용 한도(Limits) 메뉴에서 **월 사용 한도**도 걸어 두기를 권합니다.
- 키를 바꿀 때는 Render → 서비스 → **Environment**에서 `ANTHROPIC_API_KEY`만 고쳐 저장하면 됩니다.

## 활동 1 — 균형점 모델 예제 풀기

- 시소(0~10) 위의 추는 고정되어 있고, 학생은 **받침점만** 끌어서 시소가 평평해지는 곳(균형점)을 찾습니다.
- [확인] 전에는 받침대가 시소를 붙잡고 있어 기울지 않습니다. [확인]을 누르면 받침대가 빠지고 시소가 실제로 기웁니다(바닥에 닿을 때까지만).
- 10단계. 단계를 통과하면 추가 1~2개씩 늘어납니다([`lib/levelGen.ts`](lib/levelGen.ts)).
  - 새 추는 여러 자리에 고르게 놓습니다: 한 자리에 3개까지만 쌓고, 이미 추가 많은 자리·새 추끼리 같은 자리·시소 끝(1·10)은 피해서 무작위로 고릅니다. 균형점은 2~9 사이에 둡니다.
  - 한 단계에 정해진 개수(1개, 빨리 풀면 2개)만 놓습니다. 추 1개로는 추가 5개쯤 쌓인 뒤 자연수 정답을 바꿀 수 없으므로(새 추를 지금 균형점 자리에 놓는 수밖에 없음), **그런 단계만 0.5 단위 정답을 허용**합니다(로그 ‘HALF_ALLOWED’). 그 개수로 자연수·0.5 정답을 아예 만들 수 없을 때만 추를 하나 더 놓습니다(1개씩 받는 경우 보통 10단계에서 한 번, 10단계에 추 12개).
  - 새 단계의 받침점이 새 균형점과 1칸도 떨어져 있지 않으면 받침점을 멀리(가능하면 5.5, 아니면 3칸 떨어진 곳) 옮겨 놓고 시작합니다. [확인]을 누르면 AI를 기다리지 않고 규칙([`lib/activity1Rules.ts`](lib/activity1Rules.ts))으로 바로 판단합니다.
  - 난이도: 한 번에 20초 안에 풀면 추 2개, 아니면 1개를 더함. 5단계부터 한 번에 풀면 평균이 0.5 단위인 문제도 나옴.
  - 교사용 진단: 탐구 시간, 받침점을 옮긴 횟수·방향 바꿈, 평균과의 차이, 그리고 자주 보이는 오개념(가장 왼쪽·오른쪽 추의 한가운데나 가운데 놓인 추를 균형점으로 생각함)을 기록.
- **시각 힌트 (같은 단계에서 틀린 횟수에 따라)**
  - 3회: 각 추와 받침점 사이의 **거리 곡선**(왼쪽 파랑, 오른쪽 주황, 칸 수 표시)
  - 5회 이상: 여기에 **왼쪽 거리의 합 / 오른쪽 거리의 합 막대**까지 (받침점을 움직이면 실시간으로 바뀜)
  - 💡 버튼으로 켜고 끌 수 있습니다.
- 균형을 맞춘 문제는 활동 2의 3번(나만의 자료)에서 불러올 수 있습니다.

## 활동 2 — 균형점 모델과 막대 모델 연결하기

- 1번·4번 자료(3번의 ‘처음 자료’): **2, 3, 4, 4, 6, 7, 9** (평균 5). 초록색이 4·5·6일 때 넘침(= 오른쪽 거리의 합)과 모자람(= 왼쪽 거리의 합)은 각각 10·3, 7·7, 4·11입니다.
- 2번 자료: **3, 4, 5, 8, 10** (평균 6). 1번에서 막대 그림을 이미 보았으므로, 기억으로 답하지 않도록 다른 자료를 씁니다. 초록색이 4·6·7일 때 각각 11·1, 6·6, 4·9입니다.

### 그림 도구

- **초록색**: 두 그림에서 함께 움직이는 초록 표시입니다. 막대 그림에서는 **초록 선(기준선)**, 시소 그림에서는 **받침점(초록 세모)**입니다. 초록 선은 평균이 아닌 곳(4, 6 …)에도 놓이므로 ‘평균선’이라고 부르지 않습니다. 끌 때 평균에 저절로 붙지 않습니다(0.5칸 단위).
- **함께 보기**: 막대 그림과 시소 그림을 나란히 봅니다. 같은 자료는 **처음부터 같은 색·이름표**로 보여 주고, 막대나 추 하나를 누르면 다른 그림의 짝도 함께 강조됩니다.
- **바꿔 보기**: 막대 그림이 시소 그림으로 변신하는 애니메이션입니다. **3·4번에서만** 쓸 수 있고(1·2번에서는 잠겨 있음), 그 탐구에서 **먼저 생각을 저장한 뒤**(또는 도움 3단계) 쓸 수 있습니다.
- **칸** 버튼: 초록 선보다 넘친 칸(주황)과 모자란 칸(파랑)을 두 그림에 표시합니다. 학생이 켠 시점도 기록합니다.

### 탐구 구성 (4개)

학생은 **예상 저장하기 · 확인하기 · 다시 예상하기 · 생각 저장하기 · 생각 수정하기 · 다음 탐구**로 진행합니다. **답이 맞아야 넘어갈 수 있습니다**(아래 ‘답이 맞아야 넘어가요’). 별·폭죽·자동 이동은 없습니다. 그림에서 막대·추를 눌러 ‘도움이 된 부분’을 표시하는 과제는 없습니다.

| 탐구 | 학생에게 제시하는 발문 | 화면과 응답 방식 |
| --- | --- | --- |
| 1. 시소 그림 예상하기 | “시소 그림을 잠깐 가릴게요. 초록색이 4에 있을 때 시소가 어떻게 될지 막대 그림을 보고 예상해 보세요.” | 시소 그림을 덮고 초록색을 **4 → 5 → 6** 단추로 고정. 왼쪽이 내려가요 / 평평해요 / 오른쪽이 내려가요 / 아직 모르겠어요 중 선택 + **까닭 쓰기(필수)** → 예상 저장 → **확인하기**(덮개가 걷히고 시소가 천천히 기움. **예상이나 까닭이 맞지 않으면** 도움이 한 단계 올라가고 같은 초록색에서 ‘다시 예상하기’) → 초록색을 옮겨 더 살펴볼 수 있음. 세 번 모두 맞게 마치면 “막대 그림의 무엇을 보면 시소가 어떻게 될지 알 수 있나요? 예상과 달랐던 적이 있다면 무엇 때문이었는지도 써 보세요.” |
| 2. 막대 그림 예상하기 | “이번에는 새 자료예요. 막대 그림을 잠깐 가릴게요. 초록색이 4에 있을 때 시소 그림을 보고, 막대 그림에서 초록 선 위로 넘친 부분과 초록 선까지 모자란 부분 중 어느 쪽이 더 많을지 예상해 보세요.” | 막대 그림을 덮고 시소 그림만 보여 줌(초록색 **4 → 6 → 7**). 넘친 부분이 더 많아요 / 같아요 / 모자란 부분이 더 많아요 / 아직 모르겠어요 중 선택 + **까닭 쓰기(필수)** → 예상 저장 → **확인하기**(막대 그림이 나타남. **예상이나 까닭이 맞지 않으면** 도움이 한 단계 올라가고 ‘다시 예상하기’). 세 번 모두 맞게 마치면 “시소 그림의 무엇을 보면 막대 그림을 예상할 수 있나요? 1번에서 알아낸 것과 비교해 보세요.” |
| 3. 나만의 자료로 확인하기 | “그림 위 ‘새로운 자료’를 눌러 막대나 추를 놓아 나만의 자료를 만들어 보세요. 1·2번에서 알아낸 것을 막대 그림과 시소 그림에서 각각 다시 확인해 보세요.” | 예전 4번 그대로: **[처음 자료] / [새로운 자료]** 전환, 막대 그림의 ‘+’ 자리나 시소 그림의 빈 추 자리로 0~10 자료 더하기(최대 10개), 막대 끝·추를 끌어 바꾸기, ×로 지우기, **활동 1 문제 불러오기**, 모두 지우기. 초록색은 자유롭게 옮김. 쓰는 칸: **막대 그림에서**(내 자료와 평균, 넘친 칸의 합과 모자란 칸의 합) / **시소 그림에서**(평균에서 시소의 모습, 오른쪽·왼쪽 거리의 합) — 이 두 칸에 평균이나 합이 빠지면 도움이 한 단계 올라감 / **두 그림을 이어 보면**(“처음 자료와 비교해 보세요. 자료가 바뀌어도 두 그림에서 똑같이 나타나는 것은 무엇인가요?”) — 자료가 바뀌어도 같은 것(평평함, 넘친 칸과 모자란 칸이 같음)을 말하지 않으면 도움이 한 단계 올라가고 다시 써야 함 |
| 4. 자료를 바꾸어 시험하기 | “받침점은 5에 그대로 두세요. 자료의 개수나 값을 바꾼 뒤에도 시소가 평평하게 해 보세요. 바꾸기 전에 방법을 예상해 보세요.” | 방법 예상을 먼저 저장해야 처음 자료의 **복사본**을 바꿀 수 있음(받침점 5 고정). 막대 끝·추를 끌어 **값을 옮기고**, 막대 그림의 ‘+’ 자리나 시소 그림의 빈 추 자리로 **자료를 더하고**(0~10, 최대 10개), ×로 **지울 수** 있음. 자료를 바꾸는 동안 **시소는 수평으로 있고**(“지금 시소” 글도 숨김), ‘확인하기’를 누르면 그때 천천히 기움. ‘확인하기’(바꾼 것이 있고 자료가 2개 이상일 때)마다 바꾸기 전후 자료·더하거나 뺀 자료·결과를 기록(시소가 기울면 도움이 한 단계 올라가고, **한 번은 시소가 평평해져야** 다음 글로 넘어감) → “예상한 방법과 같았나요? 평평하게 하는 다른 방법도 찾아보고, 알게 된 것을 써 보세요.” |

### 답이 맞아야 넘어가요

답이 틀리면 도움이 한 단계 오르고, 맞을 때까지 다음으로 넘어가지 못합니다. 맞는지는 **규칙 검사**([`lib/answerCheck.ts`](lib/answerCheck.ts))로 바로 판단합니다(AI를 기다리지 않음).

- **1·2번 예상하기**: 고른 예상이 결과와 같아야 하고, **까닭도 맞아야** 합니다. 까닭은 ① 관련 있는 말(1번: 넘친 칸·모자란 칸 / 2번: 시소가 기운 쪽·거리)로 견주었고 ② 쓴 말이 실제 자료와 어긋나지 않고(예: 넘친 칸이 더 적다고 쓰거나 두 칸의 수를 바꿔 쓰면 틀림) ③ 넘침·모자람을 오른쪽·왼쪽에 뒤집어 잇지 않아야 합니다. “그냥”, “9가 커서”, “막대가 7개라서”, “모르겠어요”처럼 엉뚱한 까닭은 틀린 것입니다. 초등학생이 쓰는 말(위로 올라온 칸, 비어 있는 칸, 반듯해요 …)과 짧은 글, 맞춤법 오류는 인정합니다.
  - 틀리면 가려 둔 그림이 열리고 도움이 오른 뒤 **‘다시 예상하기’** 단추만 나옵니다. 같은 초록색에서 예상과 까닭을 다시 써서 맞아야 다음 초록색 단추가 열립니다(이전 까닭은 기록에 남음).
  - 세 번을 모두 맞게 마친 뒤 쓰는 정리 글도 검사합니다(1번: 넘친 칸과 모자란 칸을 견줌, 2번: 시소가 기운 쪽이나 거리를 말함, 뒤집힘 없음).
- **3번**: 막대 그림에서·시소 그림에서는 평균과 합(기존 검사), 두 그림을 이어 보면은 자료가 바뀌어도 같은 것을 말해야 합니다. 세 칸이 모두 통과해야 4번이 열립니다.
- **4번**: 바꾸기 전 예상이 시소·자료와 관련 있어야 자료를 바꿀 수 있고, 확인하기에서 **시소가 평평해진 적이 있어야** 정리 글을 쓸 수 있으며, 정리 글도 검사합니다.
- **마무리 화면**: 네 탐구를 모두 맞게 마치면 화면이 “수고했어요 / 선생님께 손을 들어 다했다고 말하세요.” 화면으로 바뀝니다(‘내 활동 다시 보기’로 돌아갈 수 있고, 교사 기록에 ‘활동 2 · 네 탐구를 모두 마침’이 남음).
- **선생님이 풀어 주기**: 도움이 4단계(선생님)에 이르면 막힌 곳에 ‘선생님 확인으로 넘어가기’가 나오고, 교사 코드(기본 `math2026`)를 입력하면 넘어갑니다(로그 ‘TEACHER_PASS’). 교사 미리보기에서는 막지 않습니다.
- 검사는 숫자와 낱말만 보는 규칙이라 완벽하지 않습니다. 맞는 답이 막히면 교사 기록(로그 ‘JUDGE’)에서 어떤 규칙 때문인지 볼 수 있습니다.

### 활동 2 설계 근거

| 설계 | 근거 |
| --- | --- |
| 막대→시소(1번)와 시소→막대(2번)를 **두 방향 모두** 예상하기 | 표상의 전환(conversion)은 방향을 바꾸면 한쪽은 쉬워도 반대쪽은 대부분 실패할 만큼 다른 과제가 됩니다(Duval, 2006, pp. 112–113, 122–123). |
| 학생이 **먼저 예상을 남기고**, 확인하기는 **정오 대신 가려 둔 그림 자체**를 보여 줌. 공개 뒤 초록색을 다시 옮겨 볼 수 있음 | 시각 피드백의 설계 조건: 선행 판단의 외현화, 판정 대신 판단이 가리키는 수학적 대상의 변화, 반복되는 재조작, 출력과 반응을 대조할 수 있는 기록(‘수학교육 이론 속의 피드백’ 0장). |
| 같은 자료를 **처음부터 같은 색·이름표**로 잇고, 학생의 생각은 **넘침·모자람 ↔ 오른쪽·왼쪽 거리**와 **양쪽이 같으면 평평**이라는 관계에 쓰게 함 | 같은 색·같은 이름표 같은 암시적 단서는 표상 사이의 연결을 돕습니다(Ainsworth, 2006, p. 194; Renkl 외, 2013 in Post & Prediger, 2024, p. 100). 연결은 요소마다(자료값, 기준과의 차이) 그리고 그 요소들 사이의 **관계**까지 드러나야 하며, 관계가 가장 덜 다루어집니다(Post & Prediger, 2024, pp. 101–102, 122). |
| 1·2번은 라운드마다 예상과 **까닭(필수)**을 남기고, 생각 정리는 **세 번을 마친 뒤 한 번** | 펼쳐 본 요소(라운드별 넘침·모자람)를 다시 하나의 관계로 묶는 과정(compacting)을 명시적으로 거치게 합니다(Post & Prediger, 2024, pp. 102, 122). |
| **나만의 자료**에서 같은 관계 확인, “자료가 바뀌어도 똑같이 나타나는 것은?” | 확장 질문 “모든 자료에서도 그 관계가 성립할까?”, 공정한 몫(고르게 하기)과 균형점의 연결(Peters 외, 2016). |
| 받침점을 고정하고 **균형을 지키며 자료의 개수나 값 바꾸기**(더하기·지우기·옮기기), **다른 방법 찾기** | 시소 위 추를 옮겨도 균형을 유지하는 활동, 평균이 같은 여러 자료 만들기(O'Dell, 2012; Van de Walle 외, Activity 20.14·Figure 20.21). |
| 도움은 **틀릴 때마다 한 단계씩**, 처음부터 대응을 보여 주지 않음 | 표상 연결을 돕는 도움의 양은 학습자에 따라 달리할 수 있는 것이 이상적이며(Ainsworth, 2006, p. 194), 시각 힌트·변환 애니메이션이 처음부터 번역을 대신해 버리면 학생이 대응을 스스로 구성할 기회가 줄어듭니다(p. 195). 활동 1의 시각 힌트도 틀린 횟수에 따라 늘어납니다. |

### 도움 (틀릴 때마다 한 단계씩)

학생이 틀릴 때마다 그 탐구의 도움이 한 단계씩 올라가 카드 아래에 나타나고, **제공 시점·종류·계기**를 기록합니다(활동 로그 ‘HELP_UP’). 학생이 누르는 ‘도움’ 단추는 없습니다.

- 1·2번: 확인하기에서 **예상이 결과와 다르거나 까닭이 맞지 않을 때**(‘아직 모르겠어요’를 고른 경우 포함). 세 번을 마친 뒤 정리하는 글이 맞지 않을 때도 올라감
- 3번: ‘막대 그림에서’·‘시소 그림에서’ 칸을 저장했는데 평균이나 넘침·모자람(양쪽 거리)의 합이 빠졌을 때, ‘두 그림을 이어 보면’이 자료가 바뀌어도 같은 것을 말하지 않을 때
- 4번: 바꾼 자료를 확인했는데 시소가 기울었을 때, 해 본 뒤 정리하는 글이 맞지 않을 때 (‘바꾸기 전 예상’이 엉뚱하면 도움 대신 무엇을 써야 하는지만 알려 줌)

| 단계 | 내용 |
| --- | --- |
| 1. 일반적인 탐색 질문 | 글만. 예: “어느 부분을 보고 그렇게 예상했나요?”, “시소가 어느 쪽으로 기울었나요? 어느 자료를 바꾸어서 그렇게 되었을까요?” 그림은 그대로 |
| 2. 살펴볼 대상 제안 | 살펴볼 대상을 말해 주고 **그 대상을 그림에 표시**(아래 표). 예: “막대 그림에 칸을 표시했어요. 초록 선 위로 넘친 칸과 초록 선까지 모자란 칸을 세어 비교해 보세요.” |
| 3. 대응을 보여 주는 도움 | 두 그림의 대응을 보여 주는 시각 힌트 (아래 표). 가려 둔 그림은 그대로 가린 채, 학생이 고른 초록색 위치도 그대로 |
| 4. 관계 설명(교사) | “선생님을 불러 함께 이야기해 보세요.” — 교사 기록에 ‘교사 확인 필요’와 마지막 계기가 남음 |

**도움 단계별로 그림에 나타나는 것** (1단계는 모든 탐구에서 그림이 그대로입니다. 시소 그림에서는 거리 곡선과 숫자를 보여 줄 때 칸 막대를 걷습니다)

| 탐구 | 2단계 | 3단계 |
| --- | --- | --- |
| 1 (막대 → 시소 예상) | 시소 그림에 **받침점에서 각 추까지의 거리를 곡선과 숫자로** 표시 (왼쪽 파랑, 오른쪽 주황) | 거리 곡선·숫자에 더해 막대 그림에 **칸 표시**(넘친 칸 주황 빗금, 모자란 칸 파랑 점선) |
| 2 (시소 → 막대 예상) | 막대 그림에 **칸 표시** | 칸 표시에 더해 시소 그림에 **거리 곡선과 숫자** |
| 3·4 | 막대 그림에 **칸 표시** + 시소 그림에 **거리 곡선과 숫자** | 여기에 더해 **모자란 칸들과 넘친 칸들을 각각 한 줄로 모으고**(막대 그림), **왼쪽 거리들과 오른쪽 거리들을 각각 한 줄로 모아**(시소 그림) 길이와 합을 비교 (위쪽에 파랑 줄·주황 줄과 합 숫자) |

힌트는 화면에 남고, 그림 위쪽 ‘힌트 닫기’ 단추로 끌 수 있으며 자료를 바꾸거나 ‘처음 상태로’를 누르면 사라집니다.

### 분석은 교사에게만

서버(`/api/analyze`)는 학생의 **전체 응답(글 + 예상, 정리 칸에서는 세 번의 예상과 결과)과 응답 당시 화면 상태**를 함께 보고, 두 그림 연결의 증거를 교사용으로 보고합니다(Claude, 키가 없거나 실패하면 규칙 분석 ‘참고용’). 학생의 진행과는 관계없습니다.

- 자료값의 대응을 글로 말했는가? (색으로 이미 이어 주므로 글에 없으면 ‘해당 없음’)
- 기준값과의 차이를 대응시켰는가? (넘침·모자람 ↔ 받침점 오른쪽·왼쪽 거리)
- 그 대응을 예상·설명의 근거로 사용했는가? (예: “시소가 오른쪽으로 기울었으니 넘친 부분이 더 많을 것이다”)
- 판단 근거가 되는 학생의 말과 예상·결과는 무엇인가? 예상과 결과가 달랐을 때 무엇을 고쳐 생각했는가?
- 평균과의 차이와 **현재 기준(실제 초록색 위치)과의 차이**를 구분해 계산합니다.
- “넘친 칸은 왼쪽 거리”처럼 대응을 뒤집어 쓴 답은 통과·불통과를 정하지 않고 **‘교사 확인 필요’**로 남깁니다.

**초등학생 기준으로 읽기** (AI 분석 프롬프트에 그대로 들어가며, 교사용 대시보드에도 보임 — [`lib/questions.ts`](lib/questions.ts)의 `STUDENT_LEVEL_GUIDE`·`AI_GUIDE`)

- 맞춤법·띄어쓰기·말투를 보지 않고, 한 문장이어도 관계가 드러나면 인정합니다. 수학 용어를 쓰지 않아도 뜻이 통하면 인정합니다(위로 올라온 칸·튀어나온 부분 = 넘친 칸, 비어 있는 칸·빈칸 = 모자란 칸, 반듯해요·가만히 있어요 = 평평).
- 숫자를 세어 말하면 더 분명한 근거로 보고, 숫자가 없어도 “넘친 칸이 더 많아서”처럼 견주면 인정합니다. 긴 글을 기대하지 않습니다.
- 오개념 신호는 flags에 짧게 남깁니다: 큰 수가 있다는 것만 보고 판단함, 추나 막대의 개수만 봄, 거리와 자료값을 섞음, 오른쪽·왼쪽과 넘침·모자람을 뒤집음.
- 규칙 분석(참고용)도 같은 말을 알아봅니다. “넘친 칸이 10칸이고 모자란 칸이 3칸이라서 오른쪽이 눌려요”처럼 두 쪽을 견주고 방향을 한 번만 말한 답을 ‘뒤집힘’으로 잘못 보지 않습니다.

### 기록 (응답 당시의 조건)

응답을 저장할 때마다 다음을 묶어 기록합니다(활동 로그·시트의 ‘응답 조건(JSON)’ 열).

- 탐구·칸·제출 차수(처음/수정), 자료값, **실제 초록색 위치**, 그때 시소의 모습, 가려 둔 그림
- 예상 내용, 예상 저장 시점과 결과 공개 시점, 정리할 때 세 번의 예상과 결과
- 나만의 자료: 만든 자료, 응답할 때 보고 있던 자료(처음/새로운)
- 응답 전에 실제로 본 강조·도움·힌트·애니메이션(그 탐구 안) + **활동 1에서 본 시각 힌트**
- 최초 응답과 수정 응답, 자료 바꾸기의 전후 자료

힌트는 실제로 재생한 것만 ‘HINT_PLAYED’로 남기고, AI가 제안한 도움은 ‘다음 도움 제안’으로 따로 남깁니다.

탐구·발문·도움 문구·분석 기준은 [`lib/questions.ts`](lib/questions.ts), 도움 단계는 [`lib/hints.ts`](lib/hints.ts)에서 고칩니다.

## 교사 미리보기 (이름: `math2026`)

첫 화면 이름 칸에 **`math2026`**을 넣고 들어가면 교사 미리보기가 켜집니다(상단에 ‘교사 미리보기’ 표시).

- 활동 2: 답을 쓰지 않아도 **네 탐구가 모두 열려** 있고(1·2번은 초록색 단추도 모두 열림), ‘바꿔 보기’도 바로 쓸 수 있습니다. 도움 단계는 ‘도움 단계 올려 보기 (교사)’ 단추로 미리 볼 수 있습니다(학생 화면에는 없음).
- 활동 1: **‘교사: 다음 단계’**로 단계를 건너뛸 수 있고, 💡 단추가 처음부터 있어 거리 곡선을 미리 켜 볼 수 있습니다. 거리의 합 막대는 학생과 같이 한 단계에서 5번 틀린 뒤에 나옵니다.
- 코드는 `VITE_TEACHER_CODE`로 바꿀 수 있습니다. 화면 코드에 들어 있는 간단한 코드이므로 비밀번호로 쓰지는 마세요.

## 교사용 대시보드 (⚙️)

오른쪽 위 ⚙️는 **교사 미리보기(이름 `math2026`)로 들어왔을 때만** 보입니다. 학생 화면에는 나타나지 않습니다. 학생 태블릿의 기록을 보려면 그 태블릿 첫 화면에서 이름을 `math2026`으로 바꾸면 됩니다(그 기기의 기록은 새로고침해도 그대로 남아 있음).

- 활동 구성(교사용 제목), 활동 2 탐구별 의도·살펴볼 것·도움 문구
- **분석 기록**: 활동 2 응답별 연결의 증거(자료값 대응·차이 대응·근거로 사용)·근거·‘교사 확인 필요’·다음 도움 제안·응답 전 본 도움, 활동 1 단계별 규칙 진단
- **Google 스프레드시트 연동**: 표시된 Apps Script 코드를 시트에 배포하고 URL을 넣으면 모든 활동 기록이 실시간으로 쌓입니다. 이번에 열이 바뀌었으므로(탐구 단계 · 학생 응답 · 응답 조건(JSON) · 교사용 분석 · 도움·힌트) 이전 시트를 쓰고 있었다면 새 시트에 코드를 다시 배포하세요.
- 활동 로그 CSV 내려받기, 이 기기 기록 지우기

**새로고침하면 학생 진행은 처음부터 다시 시작합니다.** 이름·응답·진행·푼 문제는 그 화면에서만 기억하고, 새로고침하면 지워집니다(다음 학생이 바로 새로 시작할 수 있음). 이미 저장한 응답과 그때의 조건은 아래 기기 기록에 남아 있습니다.
**기기 기록은 그대로 남습니다.** 활동 로그, 교사용 분석 기록(학생 답·판정·진단), 시트 URL은 기기 브라우저(localStorage)에 저장되어 새로고침해도 ⚙️에서 볼 수 있습니다. 지우려면 ⚙️의 ‘이 기기 기록 지우기’를 누릅니다.

```
App.tsx                      첫 화면 ↔ 활동 1/2 전환, 기록(로그·시트·AI 분석) 관리
activities/Activity1.tsx     활동 1: 단계 게임 흐름
activities/Activity2.tsx     활동 2: 네 탐구 흐름(두 방향 예상·나만의 자료·자료 바꾸기), 틀릴 때 오르는 도움, 응답 조건 기록
components/BalanceBeamStage.tsx  활동 1 시소 그림 (SVG, 터치 지원)
components/ModelStage.tsx    활동 2 막대 그림·시소 그림·변신·시각 힌트·한 그림 가리기·새 자료 만들기 (SVG, 터치 지원)
components/Home.tsx          이름 입력 + 활동 1/2 카드
components/TeacherPanel.tsx  교사용 대시보드
lib/questions.ts             활동 2 탐구·발문·도움 문구·연결 분석 기준·규칙 분석(참고용)
lib/hints.ts                 시각 힌트 종류, 도움 단계, 지원 이력 이름
lib/geometry.ts              막대 그림 → 시소 그림 변신 좌표 계산
lib/levelGen.ts              활동 1 문제 생성
lib/teacher.ts               교사 미리보기 코드
lib/activity1Rules.ts        활동 1 규칙 진단·다음 단계 난이도
server.ts                    Express 서버: /api/analyze(활동 2 연결 증거 분석, 교사용, Claude)
render.yaml                  Render 배포 설정 (학생 태블릿용 공개 주소)
```
