# 평균 탐구 활동 — 균형점 모델 × 막대 모델

초등학생이 **시소 그림(추·받침점)**과 **막대 그림**을 오가며 평균을 스스로 발견하도록 돕는 AI 통합 웹 앱입니다.
학생 화면에는 제목이 **“활동 1”, “활동 2”**로만 보입니다. 활동 2는 ‘정해진 설명을 쓰고 통과하기’가 아니라 **‘다른 그림을 예상하고, 자료를 바꾸어 시험하고, 내 자료로 확인하기’**로 진행되며, 학생에게는 판정을 보여 주지 않습니다.

| 학생에게 보이는 이름 | 교사용 제목 |
| --- | --- |
| 활동 1 | 균형점 모델 예제 풀기 |
| 활동 2 | 균형점 모델과 막대 모델 연결하기 |

## 실행하기

**필요한 것:** Node.js 20 이상

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 등 입력 (없어도 실행됨)
npm run dev                  # http://localhost:3000
```

배포(한 서버에서 화면 + API):

```bash
npm run build
NODE_ENV=production npm start
```

활동 2의 서술형 채점은 `server.ts`가 서버에서 **Claude API**를 불러 처리합니다. API 키는 서버에만 있고 학생 브라우저로 나가지 않습니다. 활동 1은 학생이 기다리지 않도록 AI 없이 규칙으로 바로 진단합니다.

### 학생 태블릿으로 쓰기 (Render 무료 배포)

학생마다 자기 태블릿으로 들어오려면 인터넷 주소가 있는 서버에 올려야 합니다. 이 저장소에는 [Render](https://render.com) 설정 파일(`render.yaml`)이 들어 있어서 아래 순서만 따르면 됩니다.

1. **코드 합치기**: GitHub의 PR 페이지에서 초록색 **Merge pull request** → **Confirm merge**를 누릅니다. (Render는 `main` 브랜치를 올립니다.)
2. **Render 가입**: render.com에서 **GitHub 계정으로 가입**합니다.
3. **배포 만들기**: 대시보드 **New** → **Blueprint** → 이 저장소를 고릅니다. 입력 칸이 나오면:
   - `ANTHROPIC_API_KEY`: Claude API 키 (채팅이나 GitHub에는 절대 붙여 넣지 마세요)
   - `VITE_TEACHER_PIN`: 교사용 대시보드 잠금 번호 (예: 네 자리 숫자) — 학생 태블릿에서 ⚙️를 눌러도 못 열게
   - `VITE_GOOGLE_SHEETS_URL`: 비워 두어도 됩니다 (아래 5번)
   - **Apply**를 누르고 3~5분 기다리면 `https://average-activity-xxxx.onrender.com` 같은 주소가 생깁니다.
4. **학생에게 주소 알려 주기**: 칠판에 적거나 QR 코드로 나눠 줍니다. 무료 요금제는 15분 동안 아무도 안 쓰면 잠들어서 첫 접속에 1분쯤 걸리니, **수업 몇 분 전에 선생님이 먼저 한 번 열어** 두세요.
5. **모든 학생 결과를 한곳에서 보기** (선택): 학생 기록은 각 태블릿에 따로 저장되므로, 한꺼번에 보려면 구글 시트를 연결합니다. 앱의 ⚙️ 교사용 대시보드에 있는 Apps Script 코드를 구글 시트([확장 프로그램] → [Apps Script])에 붙여넣고 웹 앱으로 배포한 뒤, 받은 URL을 Render의 **Environment** 화면에서 `VITE_GOOGLE_SHEETS_URL`에 넣고 **Manual Deploy**를 누릅니다. 그러면 모든 태블릿의 답안·AI 분석이 시트에 한 줄씩 쌓입니다.

요금 관리:
- Claude는 **활동 2 서술형 답을 제출할 때만** 부릅니다(활동 1은 호출 없음). 호출은 기본으로 **분당 120회, 하루 1000회**까지만 하고, 넘으면 자동으로 규칙 채점으로 대신합니다(`GRADER_MAX_CALLS_PER_MINUTE`, `GRADER_MAX_CALLS_PER_DAY`로 조정).
- Anthropic Console의 사용 한도(Limits) 메뉴에서 **월 사용 한도**도 걸어 두기를 권합니다.
- 키를 바꿀 때는 Render → 서비스 → **Environment**에서 `ANTHROPIC_API_KEY`만 고쳐 저장하면 됩니다.

## 활동 1 — 균형점 모델 예제 풀기

- 시소(0~10) 위의 추는 고정되어 있고, 학생은 **받침점만** 끌어서 시소가 평평해지는 곳(균형점)을 찾습니다.
- [확인] 전에는 받침대가 시소를 붙잡고 있어 기울지 않습니다. [확인]을 누르면 받침대가 빠지고 시소가 실제로 기웁니다(바닥에 닿을 때까지만).
- 10단계. 단계를 통과하면 추가 1~2개씩 늘어납니다. [확인]을 누르면 AI를 기다리지 않고 규칙([`lib/activity1Rules.ts`](lib/activity1Rules.ts))으로 바로 판단합니다.
  - 난이도: 한 번에 20초 안에 풀면 추 2개, 아니면 1개를 더함. 5단계부터 한 번에 풀면 평균이 0.5 단위인 문제도 나옴.
  - 교사용 진단: 탐구 시간, 받침점을 옮긴 횟수·방향 바꿈, 평균과의 차이, 그리고 자주 보이는 오개념(가장 왼쪽·오른쪽 추의 한가운데나 가운데 놓인 추를 균형점으로 생각함)을 기록.
- **시각 힌트 (같은 단계에서 틀린 횟수에 따라)**
  - 2회: 각 추와 받침점 사이의 **거리 곡선**(왼쪽 파랑, 오른쪽 주황, 칸 수 표시)
  - 3회 이상: 여기에 **왼쪽 거리의 합 / 오른쪽 거리의 합 막대**까지 (받침점을 움직이면 실시간으로 바뀜)
  - 💡 버튼으로 켜고 끌 수 있습니다.
- 균형을 맞춘 문제는 활동 2의 4번(나만의 자료)에서 불러올 수 있습니다.

## 활동 2 — 균형점 모델과 막대 모델 연결하기

- 1·3번 자료: **2, 3, 4, 4, 6, 7, 9** (평균 5). 초록색이 4·5·6일 때 넘침(= 오른쪽 거리의 합)과 모자람(= 왼쪽 거리의 합)은 각각 10·3, 7·7, 4·11입니다.
- 2번 자료: **3, 4, 5, 8, 10** (평균 6). 1번에서 막대 그림을 이미 보았으므로, 기억으로 답하지 않도록 다른 자료를 씁니다. 초록색이 4·6·7일 때 각각 11·1, 6·6, 4·9입니다.

### 그림 도구

- **초록색**: 두 그림에서 함께 움직이는 초록 표시입니다. 막대 그림에서는 **초록 선(기준선)**, 시소 그림에서는 **받침점(초록 세모)**입니다. 초록 선은 평균이 아닌 곳(4, 6 …)에도 놓이므로 ‘평균선’이라고 부르지 않습니다. 끌 때 평균에 저절로 붙지 않습니다(0.5칸 단위).
- **함께 보기**: 막대 그림과 시소 그림을 나란히 봅니다. 같은 자료는 **처음부터 같은 색·이름표**로 보여 주고, 막대나 추 하나를 누르면 다른 그림의 짝도 함께 강조됩니다.
- **바꿔 보기**: 막대 그림이 시소 그림으로 변신하는 애니메이션입니다. 그 탐구에서 **먼저 생각을 저장한 뒤**(또는 도움 3단계) 쓸 수 있고, 가려 둔 그림이 있는 동안에는 쓸 수 없습니다.
- **칸** 버튼: 초록 선보다 넘친 칸(주황)과 모자란 칸(파랑)을 두 그림에 표시합니다. 학생이 켠 시점도 기록합니다.

### 탐구 구성 (4개)

학생은 **예상 저장하기 · 확인하기 · 생각 저장하기 · 생각 수정하기 · 다음 탐구**로 진행합니다. 다음 탐구는 **할 일을 마치면** 열리고(정답 여부와 무관), 별·폭죽·자동 이동은 없습니다. 그림에서 막대·추를 눌러 ‘도움이 된 부분’을 표시하는 과제는 없습니다.

| 탐구 | 학생에게 제시하는 발문 | 화면과 응답 방식 |
| --- | --- | --- |
| 1. 시소 그림 예상하기 | “시소 그림을 잠깐 가릴게요. 초록색이 4에 있을 때 시소가 어떻게 될지 막대 그림을 보고 예상해 보세요.” | 시소 그림을 덮고 초록색을 **4 → 5 → 6** 단추로 고정. 왼쪽이 내려가요 / 평평해요 / 오른쪽이 내려가요 / 아직 모르겠어요 중 선택 + **까닭 쓰기(필수)** → 예상 저장 → **확인하기**(덮개가 걷히고 시소가 천천히 기움) → 초록색을 옮겨 더 살펴볼 수 있음. 세 번을 마치면 “막대 그림의 무엇을 보면 시소가 어떻게 될지 알 수 있나요? 예상과 달랐던 적이 있다면 무엇 때문이었는지도 써 보세요.” |
| 2. 막대 그림 예상하기 | “이번에는 새 자료예요. 막대 그림을 잠깐 가릴게요. 초록색이 4에 있을 때 시소 그림을 보고, 막대 그림에서 초록 선 위로 넘친 부분과 초록 선까지 모자란 부분 중 어느 쪽이 더 많을지 예상해 보세요.” | 막대 그림을 덮고 시소 그림만 보여 줌(초록색 **4 → 6 → 7**). 넘친 부분이 더 많아요 / 같아요 / 모자란 부분이 더 많아요 / 아직 모르겠어요 중 선택 + **까닭 쓰기(필수)** → 예상 저장 → **확인하기**(막대 그림이 칸과 함께 나타남). 세 번을 마치면 “시소 그림의 무엇을 보면 막대 그림을 예상할 수 있나요? 1번에서 알아낸 것과 비교해 보세요.” |
| 3. 자료를 바꾸어 시험하기 | “받침점은 5에 그대로 두세요. 자료 두 개를 바꾼 뒤에도 시소가 평평하게 해 보세요. 바꾸기 전에 방법을 예상해 보세요.” | 방법 예상을 먼저 저장해야 처음 자료의 **복사본**을 끌어 바꿀 수 있음(받침점 5 고정). ‘확인하기’마다 바꾸기 전후 자료와 결과를 기록 → “예상한 방법과 같았나요? 평평하게 하는 다른 방법도 찾아보고, 알게 된 것을 써 보세요.” |
| 4. 나만의 자료로 확인하기 | “그림 위 ‘새로운 자료’를 눌러 막대나 추를 놓아 나만의 자료를 만들어 보세요(활동 1에서 푼 문제를 불러와도 되고, 평균이 자연수가 되게 만들면 쉬워요). 1~3번에서 알아낸 것을 막대 그림과 시소 그림에서 각각 다시 확인해 보세요.” | 예전 4번 그대로: **[처음 자료] / [새로운 자료]** 전환, 막대 그림의 ‘+’ 자리나 시소 그림의 빈 추 자리로 0~10 자료 더하기(최대 10개), 막대 끝·추를 끌어 바꾸기, ×로 지우기, **활동 1 문제 불러오기**, 모두 지우기. 초록색은 자유롭게 옮김. 쓰는 칸: **막대 그림에서**(내 자료와 평균, 넘친 칸의 합과 모자란 칸의 합) / **시소 그림에서**(평균에서 시소의 모습, 오른쪽·왼쪽 거리의 합) / **두 그림을 이어 보면**(“처음 자료와 비교해 보세요. 자료가 바뀌어도 두 그림에서 똑같이 나타나는 것은 무엇인가요?”) |

### 탐구별 근거 연구

각 탐구가 어떤 선행연구에 기반했는지입니다. 같은 내용이 ⚙️ 교사용 대시보드의 ‘활동 2 탐구 구성’에도 나옵니다(내용은 [`lib/questions.ts`](lib/questions.ts)의 `basis`에서 고칩니다).

**1. 시소 그림 예상하기**

| 선행연구 | 연구가 말하는 것 | 이 탐구에 반영한 것 |
| --- | --- | --- |
| Duval (2006, pp. 112, 122) | 표상의 전환(conversion)은 내용이 서로 전혀 다른 두 표상에서 같은 대상을 알아보아야 하는 활동이며(p. 112), 표상을 스스로 바꾸는 능력이 수학 학습 어려움의 뿌리에 있다(p. 122). | 막대 그림만 보고 가려 둔 시소 그림의 모습을 떠올리게 한다. |
| Peters 외 (2016, p. 369) | 공정한 몫(고르게 한 값)과의 차이를 표로 정리하고 합을 구하게 하면, 학생들은 공정한 몫보다 큰 쪽과 작은 쪽의 차이가 균형을 이룬다는 것을 발견한다. | 초록 선 위로 넘친 부분과 초록 선까지 모자란 부분의 비교가 시소 예상의 근거가 되도록 한다. |
| Post & Prediger (2024, pp. 100–101, 122) | 표상을 나란히 놓거나 바꾸어 쓰는 것보다 두 표상이 어떻게 이어지는지 설명할 때 통합 수준이 가장 높다. 개념 요소 사이의 관계(이 연구에서는 부분-전체 관계)는 저절로 다루어지지 않는다. | 예상할 때마다 까닭을 꼭 쓰고, 세 번을 마친 뒤 “막대 그림의 무엇을 보면 시소를 알 수 있나요?”로 관계를 묻는다. |
| Van de Walle 외 (Ch. 20, Activity 20.15, p. 571) | 평균(균형점)을 구하기 전에 평균이 어디쯤일지 먼저 표시해 보게 한다. | 확인하기 전에 예상을 먼저 저장한다. |

### 도움 (학생이 요청할 때 한 단계씩)

‘도움’을 누를 때마다 한 단계씩 올라가고, **제공 시점과 종류를 기록**합니다. 자동으로 열리지 않습니다.

| 단계 | 내용 |
| --- | --- |
| 1. 일반적인 탐색 질문 | 예: “어느 부분을 보고 그렇게 생각했나요?” |
| 2. 살펴볼 대상 제안 | 예: “초록 선 위로 넘친 부분과 초록 선까지 모자란 부분을 비교해 보세요.”, “받침점 오른쪽 추들과 왼쪽 추들이 받침점에서 얼마나 떨어져 있는지 살펴보세요.” |
| 3. 대응을 보여 주는 도움 | 칸 표시, 양쪽 거리의 합 비교 (가려 둔 그림은 그대로 가린 채, 학생이 고른 초록색 위치도 그대로) |
| 4. 관계 설명(교사) | “선생님을 불러 함께 이야기해 보세요.” — 교사 기록에 ‘교사 확인 필요’로 남음 |

### 분석은 교사에게만

서버(`/api/analyze`)는 학생의 **전체 응답(글 + 예상, 정리 칸에서는 세 번의 예상과 결과)과 응답 당시 화면 상태**를 함께 보고, 두 그림 연결의 증거를 교사용으로 보고합니다(Claude, 키가 없거나 실패하면 규칙 분석 ‘참고용’). 학생의 진행과는 관계없습니다.

- 자료값의 대응을 글로 말했는가? (색으로 이미 이어 주므로 글에 없으면 ‘해당 없음’)
- 기준값과의 차이를 대응시켰는가? (넘침·모자람 ↔ 받침점 오른쪽·왼쪽 거리)
- 그 대응을 예상·설명의 근거로 사용했는가? (예: “시소가 오른쪽으로 기울었으니 넘친 부분이 더 많을 것이다”)
- 판단 근거가 되는 학생의 말과 예상·결과는 무엇인가? 예상과 결과가 달랐을 때 무엇을 고쳐 생각했는가?
- 평균과의 차이와 **현재 기준(실제 초록색 위치)과의 차이**를 구분해 계산합니다.
- “넘친 칸은 왼쪽 거리”처럼 대응을 뒤집어 쓴 답은 통과·불통과를 정하지 않고 **‘교사 확인 필요’**로 남깁니다.

### 기록 (응답 당시의 조건)

응답을 저장할 때마다 다음을 묶어 기록합니다(활동 로그·시트의 ‘응답 조건(JSON)’ 열).

- 탐구·칸·제출 차수(처음/수정), 자료값, **실제 초록색 위치**, 그때 시소의 모습, 가려 둔 그림
- 예상 내용, 예상 저장 시점과 결과 공개 시점, 정리할 때 세 번의 예상과 결과
- 나만의 자료: 만든 자료, 응답할 때 보고 있던 자료(처음/새로운)
- 응답 전에 실제로 본 강조·도움·힌트·애니메이션(그 탐구 안) + **활동 1에서 본 시각 힌트**
- 최초 응답과 수정 응답, 자료 바꾸기의 전후 자료

힌트는 실제로 재생한 것만 ‘HINT_PLAYED’로 남기고, AI가 제안한 도움은 ‘다음 도움 제안’으로 따로 남깁니다.

탐구·발문·도움 문구·분석 기준은 [`lib/questions.ts`](lib/questions.ts), 도움 단계는 [`lib/hints.ts`](lib/hints.ts)에서 고칩니다.

## 교사 미리보기 (이름: `math2026`)

첫 화면 이름 칸에 **`math2026`**을 넣고 들어가면 교사 미리보기가 켜집니다(상단에 ‘교사 미리보기’ 표시).

- 활동 2: 답을 쓰지 않아도 **네 탐구가 모두 열려** 있고(1·2번은 초록색 단추도 모두 열림), ‘바꿔 보기’도 바로 쓸 수 있습니다. 도움 단계는 학생과 같이 ‘도움’을 눌러 확인합니다.
- 활동 1: **‘교사: 다음 단계’**로 단계를 건너뛸 수 있고, 💡 힌트(거리 곡선·거리의 합)를 처음부터 켜 볼 수 있습니다.
